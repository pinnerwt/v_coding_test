## ADDED Requirements

### Requirement: regression_onset.py script
`task2/scripts/regression_onset.py` SHALL be a standalone script (invocable as `uv run python -m scripts.regression_onset`) that:

1. Accepts an optional `--benchmark-root` argument (default: `benchmark` relative to the working directory, matching `trends.py`'s default).
2. Accepts an optional `--output` argument (default: `<benchmark-root>/_trends/regression_onset.md`).
3. Scans all subdirectories of `benchmark-root` that do not start with `_`, reads each `results.json`, and sorts runs by `run_at` ascending — identical to the collection logic in `collect_runs` in `trends.py`.
4. For each case ID seen across all runs, computes the **regression onset**: the first branch in `run_at` order where the case status was previously passing (i.e., `status` in `{"succeeded", "unverified"}`) and the current run's status is failing (i.e., not in `{"succeeded", "unverified", "skipped"}`).
5. A case is classified as:
   - `never_passed` — it appears in at least one run with a non-skipped status and was never in a passing state.
   - `regression` — it passed in at least one earlier run and then flipped to failing; the onset branch is the first run where it failed after passing.
   - `stable` — all non-skipped appearances are passing or it is only seen with `skipped` status.
6. Writes `regression_onset.md` with the schema described in the "Regression onset report schema" requirement below.
7. Prints a summary line to stdout: `wrote regression_onset.md: N regression(s), M never-passed, K stable`.
8. Returns exit code `0` on success, `1` on any file-read or parse error (with an error message to stderr).

#### Scenario: Script writes regression_onset.md with expected sections
- **GIVEN** a `benchmark-root` containing at least two run directories where one case passes in the first run and fails in the second
- **WHEN** `uv run python -m scripts.regression_onset --benchmark-root <root>` is called
- **THEN** `<root>/_trends/regression_onset.md` SHALL be created
- **AND** SHALL contain a `## Regressions` section listing the case and its onset branch

#### Scenario: Script handles a benchmark root with no runs
- **WHEN** `regression_onset.py --benchmark-root <empty-dir>` is called
- **THEN** it SHALL write an empty-ish `regression_onset.md` (with section headers but no rows)
- **AND** SHALL return exit code `0`

#### Scenario: Script skips directories starting with underscore
- **GIVEN** a `benchmark-root` containing `_trends/results.json` and `master/results.json`
- **WHEN** `regression_onset.py` is called
- **THEN** the `_trends` run SHALL NOT appear in the output
- **AND** the `master` run SHALL be included in analysis

### Requirement: Regression onset report schema
The file `task2/benchmark/_trends/regression_onset.md` SHALL contain a top-level `# Regression Onset Report` heading, a `Generated: <ISO timestamp>` line, a `Benchmark root: <path>` line, and three subsections in this order:

- `## Regressions` — table with columns `Case`, `Onset Branch`, `Onset run_at`, `Prior passing branch`. One row per regressed case.
- `## Never Passed` — table with columns `Case`, `First seen`, `Total runs seen`. One row per case that has at least one non-skipped failing status and was never in a passing state.
- `## Stable` — table with columns `Case`, `Status`. One row per case whose non-skipped appearances are all passing, or whose only appearances are `skipped`.

Each section SHALL appear even when it has no rows (header + empty table). The `Onset Branch` column SHALL contain the branch name (the directory name under `benchmark-root`), not a git SHA, since branch names are what is recorded.

The report header SHALL include a one-line note: `Branch names map to git branches via 'git log --oneline <branch> -1'.`

#### Scenario: Regression row contains required columns
- **GIVEN** a run history where `fixture-heading` passed on branch `A` and failed on branch `B`
- **WHEN** `regression_onset.md` is generated
- **THEN** the `## Regressions` table SHALL have a row for `fixture-heading`
- **AND** the `Onset Branch` cell SHALL be `B`
- **AND** the `Prior passing branch` cell SHALL be `A`

#### Scenario: never-passed cases appear in correct section
- **GIVEN** a case `correction-l1-miss-l2-hit` that always has `status=failed` across all runs
- **WHEN** `regression_onset.md` is generated
- **THEN** the `## Never Passed` section SHALL contain a row for `correction-l1-miss-l2-hit`
- **AND** the `## Regressions` section SHALL NOT contain it

### Requirement: regression_onset.md checked into repository
The file `task2/benchmark/_trends/regression_onset.md` SHALL exist in the repository as a checked-in artifact generated by running `uv run python -m scripts.regression_onset` against the current benchmark history.

The file SHALL reflect the state of all `task2/benchmark/*/results.json` files at the time of the commit that introduces it.

The file header SHALL document the command used to regenerate it so future maintainers can update it after adding new benchmark runs.

#### Scenario: regression_onset.md is present and non-empty
- **WHEN** `task2/benchmark/_trends/regression_onset.md` is read
- **THEN** it SHALL exist
- **AND** SHALL contain `## Regressions` and `## Never Passed` headings
- **AND** SHALL contain at least one row in `## Regressions` (given the current benchmark history has known regressions)
