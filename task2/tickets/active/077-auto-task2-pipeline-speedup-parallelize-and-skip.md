77. **`/auto_task2` pipeline speedup — parallelize independent tickets and skip phases that can''t move their gate.** Today `/auto_task2` is strictly serial — one ticket → one PR → one merge → repeat — and every iteration runs every phase regardless of whether the phase can produce a meaningful signal for the picked ticket. Five levers, ordered by leverage, each individually shippable and independently testable. Filing as one ticket because they share the orchestrator surface and a single design pass that decides "what is the new pipeline shape" is cheaper than five drive-bys; the implementer is free to land them as separate PRs against this ticket. *Levers:* (1) **Parallelize independent tickets via git-worktree fan-out.** Many tickets touch disjoint files (e.g. #51 in `score.py` vs an agent-side ticket vs a benchmark-script ticket). Add a `/auto_task2 --parallel N` mode that picks N tickets at once, spawns N `/full_task2` runs in parallel git worktrees (one branch each), with a serialization point at `/done_pr` step 1a (the WebVoyager benchmark is live-only and cannot run concurrently — Qwen + the public web are shared resources) and at the merge step (master-protected, sequential PR squashes). The pre-pick filter must check `task2/scripts/score.py` / `task2/scripts/bench.py` / shared `task2/agent/*` modules for collisions and refuse to fan out tickets that touch the same hot files. Now safe to enable because #76 (plan.md → tickets/ migration) eliminated the per-PR plan.md merge-conflict surface that would have killed parallel runs. (2) **Skip the WebVoyager benchmark (`/done_pr` step 1a) when the change can''t affect agent runtime behavior.** Today the gate is `git diff --name-only origin/master...HEAD -- task2/` (any task2 change runs the benchmark). Tighten to: skip 1a when ALL touched files match `task2/scripts/{score,bench}.py`, `task2/tickets/**`, `openspec/**`, `task2/README.md`, `task2/CLAUDE.md` (i.e. process/scoreboard math/docs). Run 1a unconditionally when ANY file under `task2/agent/` or `task2/prompts/` is touched. Saves ~3-5 minutes + ~$0.40 of Qwen calls + a non-deterministic flake source per scoreboard-math or process ticket. (3) **Early-exit `/review_task2` iterations 3+ when the diff is unchanged.** The skill already notes iterations 3+ "usually converge as no-op." Add: if iteration N starts with `git rev-parse HEAD` and `git status --porcelain` identical to iteration N-1''s end-state AND `before_status` matches what `/simplify` last reviewed, skip the reviewer subagent dispatch entirely — print one line and exit. Saves one Opus subagent call per skipped iteration, which is the dominant cost in `/review_task2`. (4) **Cache `/opsx:ff` artifact templates for ticket-shape patterns.** Many tickets generate near-identical proposal/tasks structures ("fix bug in script X", "add tool Y to agent", "tighten validator Z"). Add a small `task2/scripts/opsx_ff_template.py` (or skill-level templates under `.claude/skills/opsx/templates/`) keyed on a ticket''s tier + axes + first-touched-file pattern. The sonnet subagent in `/new_task2` step 4 reads the matching template as a starting point instead of generating from scratch. Saves ~30-60s of sonnet runtime per artifact pass. Acceptance: zero regressions on artifact validity (`openspec validate`) across the existing archive. (5) **Drop `/simplify` re-dispatches on unchanged diffs (enforce harder).** `/review_task2` step 6 already says "avoid redundant /simplify dispatches" but the check is advisory. Make it a hard gate: compute a digest of `git diff master` at the start of step 6; if it matches the digest from the prior iteration''s step 6, skip the three-agent fan-out and print one line. *Concrete deliverables, may be split across PRs:* (i) a parallel-mode flag in `.claude/skills/auto_task2/SKILL.md` with worktree orchestration runbook; (ii) tightened gate in `.claude/skills/done_pr/SKILL.md` step 1a with a `git diff --name-only` classifier; (iii) early-exit block in `.claude/skills/review_task2/SKILL.md` step 1; (iv) template directory + reader in the opsx skill family; (v) digest-gated `/simplify` dispatch in step 6. Tests are skill-doc-only — no production code changes — so the test surface is "running each scenario through the skill produces the documented behavior" (paste a no-op iteration into review_task2 and confirm the reviewer subagent is NOT dispatched; paste a process-only diff into done_pr and confirm step 1a is skipped; paste two disjoint-file tickets into auto_task2 and confirm the worktree fan-out happens). *Why useful:* iteration wall-clock today is ~10-15 min/ticket dominated by (a) WebVoyager run in `/done_pr` (~3-5 min), (b) review iterations (~2-4 min each, often 3-4 iterations), (c) sonnet artifact generation (~1-2 min). Lever 2 alone halves wall-clock for ~30% of tickets (process/scoreboard); lever 1 doubles throughput for the remaining tickets when there are 2+ disjoint candidates in INDEX.md (currently 14+ active tickets, so almost always); lever 3 cuts ~25% off review wall-clock; levers 4+5 are smaller wins but compound. Combined: a typical 8-iteration `/auto_task2` run goes from ~90 min to ~30-40 min. *Risks:* (a) parallel worktrees confuse `gh pr` operations if branches collide on naming or share the same upstream master at PR-open time → mitigation is a strict per-iteration branch namespace `task2/<change>/<worktree-id>` and a sequential merge phase that pulls master between merges; (b) the "skip benchmark" gate in lever 2 misclassifies an agent-affecting change as scripts-only and lets a regression land silently → mitigation is a denylist (`task2/agent/**`, `task2/prompts/**`) that defaults to "run the benchmark" on any uncertain match, plus a periodic full-bench audit job; (c) lever 4''s template cache silently produces wrong-shape artifacts when the template assumption breaks → mitigation is `openspec validate` on every templated artifact before commit, treated as a blocking gate. *Trigger:* user-flagged on 2026-04-29 during `/auto_task2` iteration 2 — strict-serial loop wastes wall-clock and LLM tokens on tickets that don't need every phase.
