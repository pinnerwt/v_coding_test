76. **Migrate `task2/plan.md` ticket prose to `task2/tickets/` folder with `INDEX.md` as the single source of truth for selection-time data.** The current monolithic `task2/plan.md` (~415 lines, 75+ tickets across `## TDD tickets`, `## Benchmark improvements (candidates)`, and `## Undone` rubric) causes per-PR merge conflicts (every recent task2 PR has 1-3 commits touching plan.md) and forces every `/new_task2` step 1 invocation to read ~7K tokens of prose to score candidates by three axes. Target layout: `task2/tickets/{active,archive}/<NNN>-<slug>.md`, one ticket per file. Required YAML frontmatter schema: `id` (int), `slug` (kebab-case), `status` ∈ `{active, in-flight, merged, archived, dropped}`, `tier` ∈ `{1, 2, 3, 4, 5, 6}` (1=process/standards, 2=measurement, 3=stop-the-bleeding, 4=diagnostic-unblocker, 5=benchmark-impact, 6=hygiene — matches `/new_task2` step 1's tier sort), `urgency` ∈ `{P0, P1, P2, P3}` (advisory tie-breaker only), `axes: {pass_rate: int, tokens_pct: int, latency_pct: int}` (selection-time impact estimates; required even when zero), `dependencies: [<id>, ...]` (ticket ids that MUST be merged before this ticket is selectable — `/new_task2` step 2a's filter reads this; empty list when none), `pre_flight_gates: [<gate>, ...]` (gate identifiers checked at selection time, e.g. `"no-other-task2-prs-open"`, `"qwen-reachable"`; empty list when none), `evidence: [<path>, ...]` (benchmark JSONs and other artifacts the ticket cites), `related: [<id>, ...]` (overlapping tickets, advisory), `filed_pr` (int — the PR that filed the ticket prose, may equal `merged_pr` for tickets whose filing IS the work), `merged_pr` (int|null — populated by `/done_pr` step 1c on archive), `archived_at` (ISO date|null — populated on archive), `trigger` (free-text; cite the date and the workflow event that surfaced the ticket). Critical design constraint: **`task2/tickets/INDEX.md` is the strict source of truth for selection-time data** — every field `/new_task2` step 1 reads to score candidates lives in INDEX.md (id, urgency, axes, one-line summary, file path), so step 1 reads ~3K tokens (INDEX.md ~1.2K + selected ticket body ~1-2K) instead of today's ~7K (full plan.md). Per-ticket files are cold storage for ticket bodies, paged in only on selection or grep. Concrete deliverables, single PR: (1) `scripts/migrate_plan_to_tickets.py` (~150 LOC, throwaway): regex-parse plan.md ticket bodies, cross-reference urgency from `## Undone` rubric, cross-reference merged status from `openspec/changes/archive/*/proposal.md` (`grep 'ticket #N'`) and merge SHAs from `git log --grep '#N\b'`, emit per-ticket files with frontmatter populated; postcondition assert `pre_count == post_count`. (2) `scripts/regen_tickets_index.py` (~80 LOC, kept): reads every active/* and archive/* file's frontmatter, regenerates `task2/tickets/INDEX.md` deterministically (sort by id; group by urgency for the active/ section; chronological-by-archived_at for the archive/ section). (3) `task2/tickets/README.md` documenting the schema + skill consumer contract. (4) Skill updates in lockstep: `/new_task2` step 1 (read INDEX.md, parse axes, score), step 11 (write a new ticket file + run `regen_tickets_index.py`), `/done_pr` step 1b/1b' (grep target shifts to `task2/tickets/active/`), step 1c (`git mv active/<NNN>-*.md archive/`, set `merged_pr`/`archived_at`/`status: archived` in frontmatter, regen INDEX.md — one commit instead of two), `/review_task2` step 3 (cross-check now greps `task2/tickets/active/`). (5) `task2/plan.md` collapses to a stub redirecting to `task2/tickets/INDEX.md`; the prose preamble (`## Honest risks / tradeoffs`, the architectural notes) extracts to `task2/PLAN.md` as a static doc. (6) Sync test `task2/tests/test_tickets_index.py`: parse every active/archive frontmatter, assert every required field is present (including `tier`, `axes`, `dependencies`, `pre_flight_gates`), assert INDEX.md reflects the same `tier`, `urgency`, `axes`, `dependencies`, and `pre_flight_gates` for every entry — the index can't silently drift. Additional assertion: every id listed in any ticket's `dependencies:` MUST resolve to an existing ticket file (no dangling refs); a dependency on an `archived` or `merged` ticket is allowed (it just doesn't block selection), but a dependency on an unknown id fails the test. Tests: (a) the migration script run against the current plan.md produces a file count matching `grep -c '^[0-9]\+\. \*\*' task2/plan.md` from pre-migration; (b) every archived OpenSpec change under `openspec/changes/archive/*/proposal.md` whose body cites `ticket #N` produces a `task2/tickets/archive/<padded-N>-*.md` with `merged_pr` populated; (c) `regen_tickets_index.py` is idempotent (run twice, second invocation produces zero diff); (d) the schema test asserts `axes` block has all three numeric fields (pass_rate, tokens_pct, latency_pct) on every ticket, even if zero, AND asserts `tier ∈ {1..6}`, `dependencies` is a list of ints, and `pre_flight_gates` is a list of strings drawn from a known gate vocabulary (initial set: `no-other-task2-prs-open`, `qwen-reachable`, `no-benchmark-in-flight`). *Why useful:* removes a recurring merge-conflict surface (every `/done_pr` 1b/1c/1b' touch of plan.md), cuts `/new_task2` step 1 token cost by ~50% (~7K → ~3K per invocation; over an 8-iteration `/auto_task2` run that's ~32K tokens saved), and makes ticket archival a one-commit operation instead of two. Pairs with #55's regression-onset workflow (frontmatter `evidence:` field is exactly the per-case JSON path that #55 wants per ticket). *Risks:* (a) migration script mis-parses an oddly-formatted ticket → mitigation is the count-assert + per-file digest diff; (b) skill updates miss a code path → mitigation is `grep -rn 'task2/plan.md\|## Undone\|## TDD tickets\|## Benchmark improvements' .claude/` before merge and cover every hit; (c) in-flight task2 branches' plan.md edits conflict during cutover → mitigation is **must run with no other task2 PRs open** (pause `/auto_task2` for the cutover), enforced by a pre-flight `gh pr list --head 'task2/*' --state open --json number,title` check at the start of step 1 of the migration. *Trigger:* user-flagged on 2026-04-29 during `/auto_task2` iteration 2 review of PR #106 — plan.md size and per-PR merge-conflict frequency had become a real-cost item; user explicitly approved INDEX.md-as-source-of-truth design constraint after a token-cost analysis showed the naive per-file-scan would be a regression.
